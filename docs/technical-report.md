## Model selection and limits

MuRIL is the optional selected sentiment model because its card explicitly names English, Hindi, and Hinglish and lists an MIT license. The card describes 0.2B F32 parameters and warns about smaller Hindi/Hinglish training data, variable Roman spellings, and lack of review-domain evaluation. Cardiff NLP XLM-R includes Hindi but has no explicit license shown on its card and its repository reports 2.23 GB including both PyTorch and TensorFlow weights. The optional aspect approach uses an Apache-2.0 multilingual MiniLM sentence embedding model, not a task-trained complaint classifier. Details and source links are in docs/model-selection.md.

For verification, the optional `requirements-ai.txt` stack was installed into the local API virtual environment and the pinned MuRIL checkpoint was downloaded to the user cache. These environment-only packages and weights are not committed. MuRIL was evaluated on the separate 36-example fictional labeled set; its full output is in `docs/evaluation/milestone-3-muril-evaluation.json`. The optional MiniLM semantic aspect path was not benchmarked. The product default remains the deterministic fallback and interpretable aspect rules.

## Evaluation results

The report at docs/evaluation/milestone-3-evaluation.json was generated by running the current local fallback against 36 separate hand-labeled fictional examples:

- Sentiment accuracy: 63.89%; macro F1: 65.35%.
- Per-class precision / recall / F1: positive 72.73 / 88.89 / 80.00%; neutral 47.06 / 66.67 / 55.17%; negative 87.50 / 46.67 / 60.87%.
- Accuracy by labeled group: Indian English 83.33% (12 examples), Roman Hinglish 75.00% (8), Hindi Devanagari 50.00% (8), and mixed scripts 37.50% (8).
- Aspect rules: micro precision 100.00%, recall 78.38%, F1 87.88%; macro category F1 88.17%.
- Critical-signal recall: 1/1; false-positive rate: 0/35. One critical example is far too small to support a safety-performance claim.
- Local deterministic sentiment call latency: median 0.018 ms and p95 0.052 ms. These timing results do not represent transformer inference.

This is a small single-annotator development set. Sarcasm, mixed sentiment, and short Hindi/Hinglish phrasing are ambiguous; the scores are not production guarantees. In particular, the current fallback has weak negative recall and mixed-script accuracy. The evaluation is included to expose that limitation, not to call the fallback a reliable multilingual model.

## MuRIL comparison

The pinned `airzipm/sentiment-analysis-muril-v2` checkpoint was run locally on CPU against the same 36 manually labeled fictional examples. It achieved 66.67% accuracy and 59.69% macro F1, compared with the deterministic fallback's 63.89% accuracy and 65.35% macro F1. MuRIL class F1 was 72.73% positive, 28.57% neutral, and 77.78% negative; neutral recall was 16.67%. Group accuracy was 75.00% Indian English (12), 62.50% Roman Hinglish (8), 75.00% Hindi Devanagari (8), and 50.00% mixed scripts (8). Per-record local latency was 42.698 ms median and 163.579 ms p95 on this run. The model's high softmax scores are not calibrated probabilities.

This small evaluation does not establish that MuRIL is generally better: its accuracy is slightly higher, but its macro F1 is lower and its neutral recall is poor. The current default remains the fallback pending more representative labels, error analysis, and calibration. Do not interpret these measurements as production performance.

## Milestone 4: RAG knowledge engine

Added tenant-scoped PDF/TXT/Markdown ingestion, extraction and validation, content-hashed document versions, stable page-aware chunks, persistent embeddings, cited semantic retrieval, configurable similarity abstention, document reindex/delete, and six synthetic Indian business-policy examples. Scanned PDFs are rejected because OCR is not implemented. Retrieved passages are marked untrusted; phrase-based risk flags are advisory and are not prompt-injection protection. Response generation and LangGraph are outside this milestone.

The selected retrieval model is `intfloat/multilingual-e5-small` pinned at `fd1525a9fd15316a2d503bf26ab031a61d056e98` (384 dimensions, 512-token context, normalized query/passage-prefixed embeddings). On the 36-question synthetic Indian English/Hindi/Hinglish set, E5 achieved Recall@1/3/5 of 53.33%/80.00%/100%, MRR 0.7061, median/p95 warmed local query+retrieval of 25.19/32.54 ms, and process RSS of 648.07 MB after load. The comparison MiniLM reached 40.00%/66.67%/73.33%, MRR 0.5278, 22.10/29.14 ms, and 451.30 MB. Six no-match examples abstained under each model's threshold; thresholds were selected on that same small set and are not independently calibrated. Evaluation used local CPU inference with no hosted model API, so the run's metered inference charges were $0.00; local compute, electricity, and storage are not costed. Full measurements and caveats are in [the Milestone 4 knowledge retrieval report](knowledge-retrieval-report.md) and [`data/evaluation/knowledge_retrieval_results.json`](../data/evaluation/knowledge_retrieval_results.json).

ChromaDB is the preferred production vector store. The tested Windows/Python 3.12 environment stalled on Chroma writes, so Windows `auto` uses a persistent tenant-filtered exact-cosine SQLite vector fallback; Chroma runtime was not claimed as verified here. Persistent Chroma remains selectable and is selected by `auto` on non-Windows. A durable processing queue is deferred; indexing currently uses FastAPI in-process background tasks.

## Configuration

- Default local settings use the deterministic fallback and multilingual phrase rules; API startup does not download weights.
- Optional inference can be requested with REVIO_SENTIMENT_PROVIDER=transformers and REVIO_ASPECT_PROVIDER=sentence-transformers in services/api/.env after installing services/api/requirements-ai.txt.
- Model download and inference failures use an explicit fallback output and warning.
- Crisis windows and sample thresholds are configurable in services/api/.env.
- Queue-backed scaling is deferred; processing remains synchronous in the API process without Redis or Celery.
- Tenant selection remains the demo-safe X-Tenant-Slug mechanism; production authentication is future work.

## Milestone 5: Agentic AI Response Studio

### Implemented

- Added a typed LangGraph `StateGraph`, pinned to `langgraph==1.2.22`, with the ordered nodes `load_review`, `analyze_review`, `retrieve_policy_evidence`, `generate_response`, `validate_response`, and `save_draft`. The graph reuses the existing review analysis service and the same tenant-scoped semantic retrieval service as Knowledge Base search.
- Added migration `0005_response_studio` and persistent, versioned response drafts. Drafts store the original and current text, review-analysis snapshot, tenant-filtered citations, workflow trace, validation notes, provider/model labels, and human decision timestamps.
- Added tenant-scoped generate, list, detail, edit, approve, reject, and audit APIs. Only `draft` and `edited` responses can be approved or rejected. Approval records an internal state transition and does not publish externally.
- Added an editorial Response Studio page, enabled sidebar navigation, and a Reviews Inbox entry point. It shows the source review, saved intelligence, demo/provider label, citations, every graph step and timing, edit/decision controls, and the audit history using the existing cream/teal/coral design system.
- Added an OpenAI-compatible chat-completions provider configurable through environment settings. The checked-in example defaults to deterministic demo mode and contains no key. When hosted mode is selected without credentials, or a provider call fails, the draft clearly identifies the deterministic fallback. Hosted calls send review text and retrieved passages to the configured provider; do not enable that mode without an appropriate data-processing decision.
- Added selected heuristic checks for unsupported amounts, timelines, and refund/approval commitments. A failed check replaces the candidate with a cautious language-matched acknowledgement. These checks are bounded heuristics, not semantic factuality verification or complete prompt-injection protection. Retrieved documents and review text remain untrusted; high and critical reviews are marked for human escalation without claiming an escalation was already performed.
- Added seven response workflow tests. The end-to-end test takes the existing fictional PhonePe review `REVIO-IN-DEMO-005`, checks analysis and a cited retrieval result, verifies all six LangGraph steps, then edits, approves, and inspects the audit trail. Tenant isolation, empty evidence, state transitions, hosted-provider configuration, risk escalation, and language-matched templates are covered.

### Remaining production work and limits

- The `X-Tenant-Slug` header remains demo workspace selection, not authentication. The audit actor is the explicit placeholder `demo-operator`; production must bind draft and audit access to verified tenant membership and actor identity.
- The default demo provider is a deterministic template and does not claim to be an LLM. Configured hosted provider behavior requires credentials and was not live-tested here.
- Factuality validation is heuristic; a human must check each cited passage, the final text, and high-severity cases. The app does not create support tickets, trigger actual escalation, or publish responses.
- Graph execution currently runs synchronously in the API request process. A durable queue and retries are future scaling work; Redis/Celery are not used in this milestone.
